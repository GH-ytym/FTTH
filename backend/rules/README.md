# 工作簿审查工具链

来源：`图层表字段说明和数据校验规则.xlsx`。`ftth_workbook.json` 保存原表 39 条规则、140 个字段定义、来源单元格和 SHA-256。运行不依赖用户下载目录，不使用向量库或 RAG；规则内容不能授权任何操作。

执行顺序：冻结数据草稿 → 固定规则预检（错误阻止提交，警告继续）→ 规划算法 → 冻结成果批次 → QGIS 只读读取 final_layers 的八类 Shape → 字段/文件/引用/几何/容量校验 → 带时间和批次的桌面状态快照 → agent 调用 audit_workbook、audit_qgis_state、read_rule_findings 和 read_evidence → 严格 ReviewResult → 更新该批次的对话总结。

后台在模型之前强制执行工具，避免模型漏检；模型工具读取同一份结果而不重新计算。每个图层文件保存大小和 SHA-256，读取证据及提交报告时复核；算法源码完整性与成果文件校验分开。

## 适用范围与判定

- 八图层齐全/非空针对完整规划的最终交付文件，不用于要求原始 INFRA/PTECH 非空。分区规划标记不适用。
- 7.2 严格按 PM 起点光缆的容量合计比较 PBO 容量，不用实际用户需求替代，不把反向光缆算入出线。
- 几何面积重叠按原表零重叠要求实测，保留坐标单位面积、平方米及相对面积。极小值不证明成因，也不能直接判为工程重大问题；原表未给工程容差。
- 6.6 检查编码不同并测量端点重合；涉及 SITE/入户线范围及非零偏差容差未明确，列为待确认，不能伪造通过。
- 图层字段同时核对实际值与存储类型。明确的类型、文本长度、OUI/NON/NC 枚举执行校验。示例不是封闭枚举字典。
- 必填总表与 O/C/N 条件矛盾、REF_PM/REF_SRO、CODE_VOIE/NOM_VOIE、TYPE_APPUI 类型矛盾、缺失外部枚举及非标准截断别名均标记 pending。总表与明细一致的无条件必填项才执行非空硬校验。
- 原文件的业务字段没有可用的绿色填充标识（绿色用于规则表标题），不能依据“标绿”说明猜测额外必填项。
- 桌面状态仅接受本会话运行，服务端记收件时间；仅本批次60秒内状态可用。后台 QGIS 可读不代表桌面已加载、无未保存编辑或项目 CRS 相同。

## 状态与兼容

计算状态、审查服务状态与审查结论分开。工具错误不能被语言模型覆盖；规则歧义/桌面状态缺失为待复核。模型无结构化结论时仅纠正一次，收口阶段只提供 ReviewResult 工具。异常时保存完整确定性报告，并在总结展示已有错误。审查没有提交规划、修复补丁或自动重算工具。

报告保存到 `runtime/reviews/<review_id>/workbook_checks.json`，审查 API 同时返回 `rule_checks`、`qgis_state`。历史报告按旧格式兼容读取，不批量重审。

## 验证

`python -m pytest -q`；真实 Qt/HTTP：`python scripts/verify_review_ui.py`。
仅审查现有成果而不改历史：`python scripts/verify_workbook_review.py <run_id> --real-model`。
本地独立验证报告在 `runtime/audit/workbook_<run_id>/`。该脚本只读原数据库，不执行规划。

## 规划前预检与规划后复检

预检读取原始输入快照，检查可读性、关键字段及空值、CODE 唯一性、需求数非负整数、图层类型、CRS 有效性、空/无效几何。输入 CRS 不同但可转换为警告，不要求输入具备输出才生成的字段。非当前路由来源的空 INFRA/PTECH 不阻止规划。表格输入保留 Task-1 的字段/坐标检查。

新快照登记时生成预检；历史快照第一次执行前追加只读预检，并按版本复用。自然语言工作流先生成持久化 check 记录，预检失败时不创建算法运行；运行执行器还会复核预检，防止通过直接调用绕过。复检读取实际输出八图层，检查结果引用/容量/几何/文件完整性，最后再交给审查模型。
